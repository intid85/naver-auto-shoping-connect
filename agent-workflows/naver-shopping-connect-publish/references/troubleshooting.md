# 오작동 진단과 복구

## 먼저 확인할 것

1. 실행 폴더가 `C:\Users\leehansung\naver-auto`인지 확인한다. 바탕화면 복사본은 오래된 버전일 수 있다.
2. `config.json`의 `postsDir`, `startFrom`, `limit`, `mode`, `headless`를 확인한다.
3. `npm run check`로 로그인 세션을 확인한다.
4. `npm run parse`로 제목, 본문, 사진, 쇼핑커넥트 정보가 읽히는지 확인한다.
5. 패키지 루트 `recovery-manifest.json`의 SHA-256과 현재 핵심 파일 해시를 대조한다.

## 증상별 판단

### 쇼핑커넥트 카드가 한 개뿐이거나 태그 아래에 있음

- 정상 위치는 본문 최상단과 해시태그 바로 위다.
- `ZTOPZ`와 `ZBOTZ` 마커를 각각 찾아 삽입하는 로직과 카드 수 2개 검증을 확인한다.
- 상품 검색 결과를 추가한 뒤 팝업 확인 버튼까지 눌렀는지 확인한다.

### 본문에 HTTP 주소가 보임

- 발급 링크는 검색/식별용 메타데이터일 뿐 본문에 붙여넣지 않는다.
- 상품 카드는 SmartEditor의 쇼핑커넥트 도구로 추가한다.

### 영문 사진 이름 또는 자리표시자가 남음

- 사진 삽입 전에 마커를 지우지 않는다.
- 마커 텍스트가 든 `span.__se-node`를 직접 클릭해 위치를 잡는다.
- 사진 수 증가가 안정된 뒤 모든 삽입이 끝나면 마커 노드 텍스트를 비운다.
- 저장 전에 잔존 마커와 실제 이미지 수 검증을 모두 통과시킨다.

### 사진이 빠지거나 한곳에 몰림

- 문단 사이 위치 보존을 위해 슬롯별로 한 장씩 넣는다.
- 이미지 컴포넌트 수가 400ms 간격 5회 안정될 때까지 기다린다.
- 기대 사진 수와 실제 `.se-component.se-image` 수가 다르면 저장하지 않는다.

### 취소선이나 원치 않는 서식이 남음

- 붙여넣기 후 취소선, 굵게, 기울임, 밑줄 활성 상태를 명시적으로 해제한다.

### 실패했는데 초안이 생김

- 명시적 저장을 누르지 않았어도 네이버 자동저장/복구가 초안을 만들 수 있다.
- 불완전 초안은 자동 삭제하지 않는다. 사용자가 정확한 대상을 확인하고 삭제를 요청할 때만 처리한다.

### 최신 초안 확인이 헷갈림

- 목록 순서는 자동저장과 복구 때문에 신뢰하기 어렵다.
- `shot.js` 목록만으로 성공을 판정하지 말고 `post.js`의 저장 직전 검증을 우선한다.

## 기준 소스로 복구

`program-current`은 2026-09-26 실제 테스트에서 성공한 작업본이다. 덮어쓰기 전에 현재 파일을 별도 보관하고 diff를 검토한 뒤 필요한 파일만 복원한다. 로그인 세션이나 토큰은 백업에 없으므로 현재 환경에서 다시 로그인한다.
